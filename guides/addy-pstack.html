0. Step zero: turn a set on

Only one switchable set is linked at a time. The default is pocock, so neither addy nor pstack is loaded until you switch.

cd ~/repos/skills
scripts/use-skills.sh            # print the active set
scripts/use-skills.sh addy       # or: pstack | pocock | all
# then restart Claude Code
  • What the switch does: writes the name to the git-ignored .skill-set, re-runs scripts/link-skills.sh (symlinks into ~/.claude/skills and ~/.agents/skills, copies into ~/.cursor/skills, links the set's agents into ~/.claude/agents), and regenerates OpenCode commands. It only removes links it owns.
  • Always on, whatever the set: gcp/, android/, personal/ and peer-review/.
  • Invoke names carry the prefix. You type /addy-spec or /pstack-poteto-mode. The skill listing may show the upstream name in brackets, like addy-spec (spec).
  • all is noisy. The three sets each bring their own TDD, review and planning flow, and pstack's tdd and teach share frontmatter names with pocock's. Use all only to compare.

pocock

Grill to shared understanding, publish specs and tracer-bullet tickets, build deep modules test-first. Pick it when the work runs through the issue tracker.

addy

A senior engineer's phase-by-phase playbook (spec, plan, build, test, review, ship). Most skills fire on their own; the commands are the steering wheel. Pick it for broad lifecycle coverage including security, perf, CI and launch checklists.

pstack

poteto's opinionated style: named principles, prove-it-works, deliberate subagent fan-out, adversarial review, no AI-sounding prose. Everything goes through one front door. Pick it for long autonomous runs with strict verification, and when you are happy to drive with slash commands.

Cost note

pstack spends extra tokens on subagents and review panels by design. addy's /addy-ship spawns three agents too. Save both for work that needs the rigour.

Five parts: goal, done check, the proof you want to see, what you already know, real constraints. Leave out the "how". The last line works around the Claude Code invocation issue.

/pstack-poteto-mode <symptom>. known: <log line, job id, when it started>.

Mid-run steering: name a principle ("apply prove it works, show me the real output"). Short follow-ups are fine: "do it", "continue". Say "new task" to re-match a playbook.

Personas never call each other; the commands orchestrate. A same-named agent in .claude/agents/ overrides these.

addy gotchas

  • chrome-devtools MCP isn't configured. You have claude-in-chrome, which is a different server. Browser testing, the browser half of /addy-test and deep /addy-webperf expect npx -y chrome-devtools-mcp@latest --isolated in .mcp.json. Avoid --autoConnect: it exposes your logged-in browser.
  • Severity labels differ by file. Read them as one scale: Critical = must fix; Important / Required = fix or defer with reason; Suggestion / Optional / Nit / FYI = your call.
  • Repo-touching commands. /addy-constraints installs tools and edits package.json and your project CLAUDE.md. /addy-build commits per task.
  • JS/TS-flavoured examples. The TDD skill says to discover the repo's own commands first, so Gradle / Android works, but the examples won't match.
  • idea-refine points at a script path that doesn't resolve here (it only does mkdir -p docs/ideas) and asks via AskUserQuestion pickers.
  • "Plan mode" in /addy-plan just means read-only. It isn't Claude Code's plan mode.
  • Cross-model doubt must run in the main session (subagents can't spawn subagents) and needs gemini or codex on PATH.

4. pstack deep dive

Source: the pstack/ plugin of cursor/plugins by poteto, built for Cursor. Guide pages: pstack/docs/guide. 52 skills: 28 workflow skills and 24 principles. All of them are user-invoked except pstack-setup-pstack, so nothing in pstack fires on its own.

The one rule: start every non-trivial task with /pstack-poteto-mode <goal>. Give it a goal and a way to check it. Don't list skills: a hand-written sequence drops or reorders steps. Ask /pstack-poteto-help if unsure; it answers and hands you a prompt but never starts work.

How poteto-mode runs

  1. Reads the principles index; it may only cite principles whose skill it actually read.
  2. Matches your task to one of 23 playbooks. Large, cross-cutting or "step away" work goes to figure-it-out; multi-day programs go to orchestrate.
  3. Opens a todo list whose first items are the playbook steps copied verbatim. Skipped steps stay as skip: <reason>.
  4. Calls other skills as triggers fire: non-trivial change → how; crosses a function boundary → architect; fan-out → swarm or arena; contested design → interrogate; prose → unslop; docs/PRs → technical-writing; before review → no-comments; perf numbers → benchmark-checklist; long or unattended → show-me-your-work.
  5. Delegates code to background pstack-poteto-agent subagents with file pointers, not pasted context. The parent reviews every diff.

Autonomy

Acts on reversible work without asking. Always pauses for force-push, deploys, data deletion, customer messages. "No" is an allowed answer.

Reply style

Short declarative sentences. Every claim tagged measured, inferred or guess. Impact framed for the user and the next maintainer.

Upstream guide, distilled

  • Design ladder: interrogate alone for small changes; architect for boundary-crossing; arena for standalone decisions; swarm for coverage; prototype instead of debating; plan only after the design settles.
  • Earn trust before looping: do the task once by hand, give the agent your tools, make every stage prove its work, read some transcripts.
  • /loop needs a predicate, not a duration. Ask for real output, not a green build.
  • Parallel agents get their own worktree.
  • The verification skill pays off most: /pstack-create-verification-skill once per app (tell it to write to .claude/skills/, not .cursor/skills/).
  • Fix a broken skill in its own PR.

5. pstack in Claude Code: what breaks

pstack was written for Cursor. Most of it still runs, but five things cut across everything.

A. Skills can't call each other. Upstream marks every skill disable-model-invocation: true, which in Claude Code blocks the model from loading them with the Skill tool. poteto-mode refers to how, architect, interrogate and the principles by name only, so it can't "run" them.

Workaround: the last line of the prompt templates above tells it to Read ~/.claude/skills/pstack-<name>/SKILL.md instead. You can also invoke a sub-skill yourself (/pstack-architect) when it reaches that step.

B. No model diversity. Defaults are Cursor slugs (Grok, Opus xhigh). Claude Code's Agent tool takes only sonnet / opus / haiku, so everything runs on Claude. Tiering still works: opus for judgement, sonnet or haiku for helpers. interrogate, arena, architect and eval lose most of their cross-model independence.

C. Cursor-only tools. /deslop → /simplify or /pstack-unslop. control-ui / control-cli → claude-in-chrome, /run, or a project verify skill. create-skill → writing-for-agents or anthropic-skills:skill-creator. AskQuestion → plain questions.

D. Transcripts. Skills look in ~/.cursor/projects/<slug>/agent-transcripts/. Claude Code keeps them at ~/.claude/projects/<slug>/*.jsonl. Affects recall, reflect, automate-me, session-pickup, eval, show-me-your-work.

E. Agents need linking. pstack-poteto-agent and pstack-comment-sicko work once use-skills.sh pstack has run. Their is_background flag is ignored.

Don't run worktree-cleanup unattended. Its audit script reads Cursor transcripts and uses BSD stat -f, which fails on Linux, so the "a recent chat still uses this worktree" signal is always empty and live worktrees can look prunable. It still pauses on uncommitted work. The simulator step is macOS-only.

Broken outright: pstack-setup-pstack (writes a Cursor .mdc rule Claude Code never loads) and /pstack-make-bot-ui (needs Cursor's update_state and a Grok bot). Heavy: orchestrate assumes Cursor cloud workers; the bun scripts/orch part runs, but "hundreds of subagents" doesn't.

Clean: investigation, prototype, runtime-forensics, trace-forensics, pause-safely, babysit, shipping; teach, bro, ketchup, blast-radius, correct, tdd, unslop, technical-writing, benchmark-checklist, typescript-best-practices, figure-it-out, no-comments; all principles (read, not invoked).
